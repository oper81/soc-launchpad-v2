# Пример отчёта L1 (по результатам default.json)

> **Примечание:** это пример того, как выглядит разбор очереди алертов для
> портфолио. Цифры взяты из прогона `default.json` (seed=2026) с включенным
> тюнингом (11 алертов).

## Контекст
- Стенд: синтетические логи (sshd, nginx, kern, auditd).
- Период: 7 дней.
- Обнаружено: 11 алертов.

## Разбор алертов

**Алерт 1-2: SSH Brute Force (100100) + SSH Compromise (100101)**
- Хост: `web01`
- Детали: 20+ неудачных попыток пароля от `192.0.2.10` (root), затем успешный вход.
- Вердикт: **True Positive**.
- Действия L1: Изолировать хост, сбросить пароль root, проверить историю команд. IP `192.0.2.10` — добавить в блок-лист.

**Алерты 3-7: Web Exploitation (100110)**
- Хост: `web01`
- Детали: Запросы к `/.env`, `/admin`, `/../../etc/passwd` и т.д. от `198.51.100.7`.
- Вердикт: **True Positive**.
- Действия L1: Проверить веб-сервер на компрометацию (webshell). IP добавить в блок-лист.

**Алерты 8-9: Port Scan (100120)**
- Хост: `db01`
- Детали: Множественные DROP от `203.0.113.9`.
- Вердикт: **True Positive**.
- Действия L1: Сканирование портов. IP добавить в блок-лист.

**Алерты 10-11: Valid Account After Hours (100140)**
- Хост: `web01`
- Детали: Вход пользователя `alice` в 02:00 ночи от `198.51.100.30`.
- Вердикт: **True Positive** (или False Positive, если админ подтвердит ночную работу).
- Действия L1: Связаться с пользователем `alice`, проверить активность.

**Не обнаружено (пропущено):**
- `slow_port_scan`: Медленное сканирование от `192.0.2.20`. Пороговое правило 100120 (15 событий за 60 секунд) не сработало. Требуется внедрение поведенческого анализа или увеличение окна (что повысит FP).

**Ложные срабатывания (устранены тюнингом):**
- Сканирование Nessus (ловушка `nessus_scan`) — исключено по IP.
- Запуск тестов из `/tmp` (ловушка `dev_tmp_binary`) — исключено по пути.
